# EVORI Drone Data Platform — MVP

MVP веб-платформы для единого сценария работы с данными аэросъёмки БПЛА: **проект → загрузка данных → импорт обработанного георезультата → карта → измерения → отчёт**.

Проект подготовлен по Техническому заданию ТОО «Инмаро» / EVORI. Цель MVP — подтвердить техническую реализуемость единого пользовательского процесса, а не создать промышленную фотограмметрическую платформу.

## Реализовано

- JWT-авторизация, вход/выход.
- Создание и список проектов с полями из ТЗ: название, заказчик, местоположение, дата обследования, тип объекта, описание, статус.
- Загрузка JPG/JPEG, PNG, GeoTIFF, ZIP, CSV и GIS-файлов.
- Отдельный сценарий «Импорт результата» — вариант В из ТЗ: готовый результат обработки автоматически привязывается к выбранному проекту.
- GIS-интерфейс Leaflet + OpenStreetMap.
- Визуализация импортированного GeoJSON и распространённых GeoTIFF непосредственно на карте.
- Базовые измерения расстояния и площади.
- Сохранение измерений в проекте без повторного дубляжа уже сохранённых записей.
- Авторизованное формирование печатного HTML-отчёта с возможностью сохранения в PDF средствами браузера.
- Docker Compose.
- Backend API tests + GitHub Actions для backend и frontend build.
- Архитектурная документация, матрица приёмки, demo-сценарий и roadmap.

## Быстрый запуск

Требуются Docker Desktop и Git.

    docker compose up --build

Открыть: http://localhost:5173
API: http://localhost:8000/docs

Демо-пользователь:

- login: demo
- password: demo123

Перед эксплуатацией обязательно заменить EVORI_SECRET и демо-пароль. Демо-учётные данные предназначены только для приёмочной демонстрации.

## Приёмочный сценарий

1. Войти.
2. Создать проект.
3. Заполнить параметры объекта.
4. Загрузить исходные данные.
5. Нажать «Импорт результата» и выбрать sample-data/demo.geojson либо GeoTIFF.
6. Убедиться, что результат отображается на карте.
7. Нарисовать линию и полигон.
8. Нажать «Сохранить измерения».
9. Нажать «Отчёт» и сохранить страницу как PDF.

Подробная матрица: docs/ACCEPTANCE.md.
Демонстрация: docs/DEMO.md.

## Архитектура

- frontend/ — React + Vite + Leaflet.
- backend/ — FastAPI, JWT, SQLite и файловое хранилище MVP.
- sample-data/ — небольшой GeoJSON для демонстрации импорта результата.
- docs/ — архитектура, приёмка, demo, лицензии и roadmap.

SQLite выбран для автономного запуска MVP без внешней инфраструктуры. Следующий этап — PostgreSQL/PostGIS + объектное хранилище + очередь обработки.

## Ограничения MVP

В первый этап сознательно не входят собственный фотограмметрический движок, полноценный AI/CV, автоматическое распознавание дефектов, Change Detection, LiDAR, сложные 3D-сценарии, мобильное приложение, CRM/ERP, биллинг, сложная ролевая модель, промышленная отказоустойчивость и обработка десятков/сотен ГБ.

Это соответствует разделу 11 ТЗ и оставляет архитектурный задел для последующих этапов.

## Статус

**MVP готов к техническому review и демонстрации заказчику.**

Перед production-развёртыванием необходимо заменить demo credentials/secret, вынести файлы в объектное хранилище, перейти на PostgreSQL/PostGIS, добавить аудит, резервное копирование, ограничения upload size и production reverse proxy.
